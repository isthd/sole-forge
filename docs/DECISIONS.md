# 判断の記録（DECISIONS）

企画書（docs/PLAN.md）に書かれていない点、解釈が必要だった点を、企画書の方針に沿って決めた記録です。

## 全体・技術選定

| # | 判断 | 理由 |
|---|---|---|
| D1 | React 18 + **@react-three/fiber v8 + drei v9** を採用 | 企画書は React 18 指定。R3F v9 は React 19 必須のため v8 系を選んだ |
| D2 | Vite 6 + **Vitest 3** | Vitest 2 は内部に Vite 5 を持ち、Vite 6 と型が衝突したため |
| D3 | `npm test` は Vitest（単体）のみ。オフライン E2E は `npm run test:e2e`（ビルド → `vite preview` → Playwright） | E2E は本番ビルドと Service Worker が必要で時間もかかるため分離。完了の定義では両方を必須にした |
| D4 | ディレクトリは企画書の指定どおり `src/models`, `src/renderers`, `src/store`, `src/db`, `src/features/editor|shelf|settings` | 企画書「CLAUDE.md に書くこと」に従った |
| D5 | ストアを `window.__sf` に公開 | E2E で作品データを検証するため。外部通信はしない |
| D6 | git リポジトリは作成していない | 指示に無かったため。必要なら `git init` してください |

## 3D モデル（hightop-01）

| # | 判断 | 理由 |
|---|---|---|
| M1 | 座標系: x = かかと(-)→つま先(+), y = 上, z = 外側(+)/内側(-)。単位は約 10cm（全長 3.0） | 寸法パラメータを直感的に扱うため |
| M2 | 寸法パラメータ: 全長・半幅・足形の丸み・アウトソール厚・ソール厚・**つま先の反り**・甲の高さ・履き口の高さ（前/後ろ） | 企画書の「長さ・高さ・ソール厚・つま先の反り」を含む |
| M3 | **アッパー = 足形の輪郭（下端）と履き口の輪郭（上端）を、断面ごとの 3 次ベジェ曲線でつないだ曲面**。トゥ・ヒール・アイステイ・サイドパネルはアッパー曲面を法線方向に少し浮かせた「重ね（オーバーレイ）」パーツ | 企画書「断面の曲線をつないだ曲面」。実物の縫い重ね構造に近く、パーツ境界で隙間やちらつきが出ない |
| M4 | ライニングは内側に 0.04 ずらした曲面＋履き口の丸いパッド | 履き口から内側が見えるため |
| M5 | ミッドソール・アウトソールは足形の輪郭を `ExtrudeGeometry` で押し出し（ベベル付き）、靴ひもは `TubeGeometry`（クリスクロス 13 本＋蝶結び） | 企画書の指定どおり |
| M6 | **表示は片足（右足）1 つ**。ポリゴン予算は「1 足 = 左右 2 つ」で 5 万以下と解釈し、片側 **24,584** ポリゴン（左右で 49,168）に収めた | 「1 足」は日本語で左右一組を指すことが多いため、厳しい方の解釈で満たした |
| M7 | サイドパネルは「角を落とした六角形のプレート」形状 | 当初の斜めストライプ案が実在ブランドのマークを連想させたため変更。アプリアイコンも 3 本線を避けて同じプレート意匠にした |
| M8 | ジオメトリは型ごとに 1 回だけ生成してキャッシュし、色・素材の変更ではマテリアルだけ差し替える | スマホでの軽さ |
| M9 | **ベース型は 4 種類**（ハイカット 01 / ミッドカット 01 / ローカット 01 / 厚底ロー 01）。形の生成は `sneakerBuilder.ts` に共通化し、各型は寸法パラメータ（履き口の高さ・くるぶし下の切れ込み `collarDip`・ソール厚など）だけを持つ | パーツ構成とポリゴン数が全型で同じになり、配色・デカールをそのまま引き継げる |
| M10 | 型はエディタで切り替える（PC は左の MODEL、スマホは「型」タブ）。切り替えは Undo 1 手。デカールは高さをアッパーの高さの比率で写してから表面へ投影し直し、当たらなければ真横 → 少しずつ下げて探す。カメラは新しい型の標準角度に戻す | 作品を作り直さずに型だけ試せるように。ハイカットの高い位置のデカールもローカットで消えない |
| M11 | 新規作成ボタン（エディタ）は今開いている型で作る。JSON 読み込みで不明な型はハイカット 01 にする | schemaVersion を上げずに互換を保つ |

## エディタ

| # | 判断 | 理由 |
|---|---|---|
| E1 | 「パーツ選択のハイライト」は、選んだ直後に **約 1.1 秒だけ** ライムで発光させる（常時ではない） | 常時発光させると、選んでいるパーツの本当の色が分からなくなるため |
| E2 | **「配色の左右コピー」= デカールを外側 ⇔ 内側へ鏡像コピー**（コピー先の既存デカールは置き換え、中央付近 \|z\|<0.05 のものは対象外） | データモデルの `parts` は左右共通（パーツごとに 1 色）なので配色は常に左右対称。左右で違いが出るのはデカールだけのため、それを左右にそろえる機能とした |
| E3 | Undo 履歴は zundo で **最大 100 手**。カラーピッカーやスライダーのドラッグ中の連続変更は 400ms 以内なら 1 手にまとめる。ボタン操作は必ず 1 手 | 50 手以上の要件を余裕をもって満たし、ドラッグで履歴が埋まらないように |
| E4 | 履歴の対象は作品データのみ。パーツ選択・カメラ角度は対象外 | 角度を変えただけで Undo が消費されないように |
| E5 | デカールの貼り付けはモデル表面をタップした点に `DecalGeometry` で投影。**靴ひもは貼り付け対象から除外**（奥の面に貼る） | 細いチューブに貼っても見えないため |
| E6 | デカールの `scale` = 長辺の長さ（モデル単位）、`rotation` = 度（-180〜180）、`flip` = テクスチャを左右反転、`z` = 重ね順（0 が最背面） | データモデルの値の意味を明確化 |
| E7 | 移動は 3 通り: ①「移動モード」でモデル上をドラッグ（その間は回転を止める）②矢印ボタン（接平面上でずらして表面に投影し直す）③キーボード矢印 | スマホでもマウスでも正確に動かせるように |
| E8 | 付属ロゴは 6 種（ヘックス SF / スパーク / アンビル / ボルトリング / アイ / ワードマーク）。すべて Canvas の Path2D とテキストで描くオリジナル | 実在ブランド回避・外部ファイル不要 |
| E9 | 文字デカールのフォントは同梱の Oswald / Noto Sans JP / Permanent Marker から選択 | オフラインで確実に描けるもの |
| E10 | 読み込んだ画像は 1024px 以下の PNG に縮小して IndexedDB に保存（キー `img:<uuid>`） | テクスチャ 1024px 以下のルール |
| E11 | ランダム配色は配色理論（単色・類似色・補色・トライアド・無彩色＋差し色）からランダムに選び、パーツの役割ごとに明度を変える。35% の確率で 1 パーツに柄を入れる | 「それっぽい」配色になるように |
| E12 | 素材の PBR: レザー（粗さ 0.5＋シボのノーマルマップ）、スエード（粗さ 0.98＋sheen）、メッシュ（六角穴のノーマルマップ）、キャンバス（織り目）、パテント（粗さ 0.12＋クリアコート）。ノーマルマップは 512px を Canvas で生成 | 企画書「粗さ・光沢・ノーマルマップ」 |
| E13 | 柄テクスチャは Canvas で生成（グラデーション 4×256 / チェック・ドット 256 / 迷彩 512、すべて継ぎ目なしでタイル）。グラデーションは下→上。柄の色は 2〜4 色 | テクスチャ 1024px 以下 |
| E14 | ライティングは three の `RoomEnvironment` をコードで生成した環境光＋平行光 2 灯＋半球光。地面の影は Canvas の放射グラデーション | 外部 HDR を読まずに素材の質感を出すため |
| E15 | 新規作品の名前は「SNEAKER #NN」 | 棚で区別しやすく |

## 棚・書き出し・保存

| # | 判断 | 理由 |
|---|---|---|
| S1 | 自動保存は変更から 350ms 後。画面を閉じる/隠すときも即保存 | 企画書「IndexedDB に自動保存」 |
| S2 | サムネイルは変更が 1.2 秒止まったら裏で再生成。**角度は全作品共通の 3/4 ビュー**、384px・透過 PNG、Blob キーは `thumb:<作品ID>` | 棚で並べたときにそろって見えるように |
| S3 | 棚の並べ替え: PC はドラッグ＆ドロップ、全端末でメニューの「前へ／後ろへ移動」。並び順を「手動／更新順／名前順」で切り替え可能（手動のときだけ並べ替え可） | タッチでのドラッグ＆ドロップは誤操作が多いため |
| S4 | 棚のカード: タップで 3D ビューア、長押し（520ms）・右クリック・「…」ボタンでメニュー | 企画書「タップで拡大、長押し（右クリック）でメニュー」 |
| S5 | 単体 PNG の「好きな角度」= エディタで今見ている角度（棚のビューアからはビューアで回した角度）。基準 1024px 四方 × 1x/2x/4x（最大 4096px） | 企画書の「好きな角度を高解像度で再レンダリング」 |
| S6 | GPU の上限（MAX_RENDERBUFFER_SIZE）が 4096 未満の端末では上限サイズで書き出し、トーストで実寸を知らせる | 古いスマホ対策 |
| S7 | 棚全体 PNG は 4 列のラック風レイアウトに、各作品を書き出し倍率で再レンダリングして並べる。iOS Safari の Canvas 上限（約 1,677 万画素）を超える場合は倍率を自動で下げる | サムネイルの拡大ではなく高精細に |
| S8 | JSON バックアップ = `{ app, schemaVersion, exportedAt, designs, blobs }`。blobs は画像とサムネイルの data URL（Base64） | 企画書「画像を Base64 に埋め込んだ 1 ファイル」 |
| S9 | 読み込みは**同じ ID の作品は上書き、新しい作品は棚の末尾に追加**。読み込み時に schemaVersion でマイグレーション（現在は v1 のみ。変換関数の登録表を用意）し、各項目を検証・補正（不正な色は既定色に、欠けたパーツは補完） | 端末間移行で同じファイルを何度読んでも重複しない |
| S10 | 作品削除時に、どこからも参照されない画像 Blob を掃除（直近 10 分以内に読み込んだ未使用画像は残す） | 容量の節約と、貼る前の画像を消さないため |
| S11 | 設定画面に「永続化をリクエスト」（navigator.storage.persist）と「すべてのデータを削除」を追加 | ブラウザによる自動削除を防ぐ手段として |

## PWA・フォント・性能

| # | 判断 | 理由 |
|---|---|---|
| P1 | フォントは @fontsource から Noto Sans JP（400/700）、Oswald（500/700、見出しのコンデンス体）、Permanent Marker（400、デカール用）を同梱 | 企画書「見出しは太いコンデンス体、本文は Noto Sans JP」 |
| P2 | Service Worker（generateSW / autoUpdate）で js・css・html・svg・png・**woff2** をすべてプリキャッシュ（278 ファイル / 約 7.3MB、うち woff2 が 259） | Service Worker が使えるブラウザはすべて woff2 対応のため、旧形式の woff はプリキャッシュしない |
| P3 | ランタイムキャッシュ（外部オリジン）は一切定義しない | 外部通信禁止の方針 |
| P4 | アイコン PNG（192/512/maskable/apple-touch）は `scripts/gen-icons.mjs` で SVG から生成して `public/` に同梱 | 外部ツール不要で再生成できる |
| P5 | 描画は `frameloop="demand"`（操作中だけ描画）、画素密度は最大 1.75 倍 | スマホでの電池と発熱、30fps 以上の確保 |
| P6 | 回転 FPS の計測は、カメラを毎フレーム回し続けるテスト用フック（`window.__sfSpin`）で行う | ドラッグ操作と同じ描画負荷を安定して再現するため |
| P7 | スマホ判定は画面幅 900px 未満。スマホでは下部タブ＋ボトムシート、アクティブなタブをもう一度タップするとシートを閉じて 3D を広く使える | 企画書の画面構成 |
