## 受け入れ基準ごとの結果

### 1. 機内モードでアプリを開き、新規作成から保存まで全操作できる — ✅ 合格
- 初回アクセスで Service Worker がプリキャッシュ（キャッシュ内 272 件以上）を完了 → ブラウザをオフライン（`context.setOffline(true)`、`navigator.onLine === false`）にして再読み込み。
- オフラインのまま: 起動、同梱フォント 3 種の読み込み、新規作成、色・素材・柄、ロゴ・画像・文字の貼り付け、Undo/Redo、名前変更、棚の複製・並べ替え・削除・お気に入り、PNG 書き出し（単体・棚）、再起動、JSON 書き出しまで通しで成功。
- 補足: 実機の「機内モード」ではなく、Chromium のオフライン状態で検証しています（Service Worker の挙動は同じです）。

### 2. 3D ビューで回転・拡大・プリセット視点の切り替えができる — ✅ 合格
- 正面・横・後ろ・上の 4 プリセットで、カメラが各プリセット位置（誤差 0.6 以内）へ移動。
- ドラッグで回転（カメラ位置が変化）、ホイールで拡大（注視点までの距離が縮む）、キー 1〜4 でも切り替え。
- スマホ向けのピンチ拡大・2 本指パンは OrbitControls 標準のタッチ操作（自動テストは未実施。下の「未確認の点」参照）。

### 3. 10 パーツすべてに色・素材・柄を設定できる — ✅ 合格
- E2E: 10 パーツそれぞれを UI で選び、パレットの色・素材（5 種を順に）・柄（4 種を順に）を設定し、保存データに反映されたことを確認。
- 単体テスト: 10 パーツ × 素材 5 種 × 柄 4 種のすべての組み合わせと柄の解除。

### 4. ロゴ・画像・文字をモデル表面に貼り、移動・拡大・回転できる — ✅ 合格
- ロゴ（スパーク）、画像（PNG ファイルを読み込み）、文字（「FORGE 01」）を 3D ビューをタップして貼り付け（3 つとも靴ひも以外のパーツ表面に投影）。
- 移動（矢印ボタン／移動モードでのドラッグの両方で位置が変化）、拡大（0.9）、回転（30°）、左右反転、重ね順（最背面 = 0）を確認。

### 5. Undo/Redo が 50 手以上効く — ✅ 合格
- E2E: 色を 55 回変更 → Ctrl+Z を 55 回で元の色に戻り、Ctrl+Shift+Z を 55 回でやり直し。
- 単体テスト: 60 手の Undo/Redo。履歴の上限は 100 手。

### 6. 棚で並べ替え・複製・削除ができ、再起動後も残っている — ✅ 合格
- 棚で複製 → 「前へ移動」で並べ替え → さらに複製して削除 → お気に入り。
- オフラインのままページを再読み込みし、件数・並び順・お気に入りがそのまま残っていることを確認。
- 単体テスト: DB 接続を閉じて開き直しても、並べ替え・複製・削除・名前変更が残る。

### 7. 単体（好きな角度）と棚全体を PNG（最大 4x）で書き出せる — ✅ 合格
- 単体: エディタで「横」に回した角度で、透過・4x → **4096 × 4096 px**（`single-4x.png`）。背景あり・1x → 1024 × 1024 px。
- 棚全体: 4x → **3920 × 2152 px**（`shelf-4x.png`、作品数に応じて縦に伸びる）。

### 8. JSON で書き出した全作品を別端末で読み込んで復元できる — ✅ 合格
- 「別端末」= 新しいブラウザコンテキスト（保存データが空、スマホ画面 390px）で、書き出した JSON を設定画面から読み込み。
- 全作品名・画像デカールの画像データ（IndexedDB の Blob）・デカール 3 つを持つ作品をエディタで開けることを確認。
- 単体テスト: 書き出し → 空の DB へ読み込み → 色・素材・柄・デカール・画像のバイト列まで一致。同じファイルを再度読み込むと重複せず上書き。未来の schemaVersion や壊れたデータは拒否・補正。

### 9. 幅 360px のスマホと 1440px の PC で操作が破綻せず、スマホでも回転が 30fps 以上 — ✅ 合格
- レイアウト: 360×740（スマホ相当、タッチ・画素密度 2）と 1440×900 で、エディタ・棚・設定の全画面と、スマホの全 5 タブ（パーツ／色／素材／柄／デカール）を開いた状態で**横方向のはみ出し 0**。スマホではボトムシートからパーツを選んで色を変更できることも確認。
- 回転の描画速度（カメラを回し続けて 3〜4 秒間のフレーム数を計測）:

| 条件 | FPS |
|---|---|
| 360px スマホ相当（画素密度 2） | **59.7 fps** |
| 360px スマホ相当 ＋ CPU を 4 倍遅く（画素密度 3） | **59.9 fps** |
| 1440px PC | **60.0 fps** |

- ポリゴン数: 片足 **24,584**（左右 1 足で 49,168 ≤ 5 万）。テクスチャはすべて 1024px 以下（ノーマルマップ 512px、柄 ≤512px、デカール ≤1024px）。
- 補足: GPU はこの PC の Intel Arc を使った計測で、実機のスマホでは計測していません。

## 未確認の点・注意

- **実機での確認は未実施**です（実際のスマホでの FPS、iOS Safari の挙動、PWA のホーム画面追加、機内モード）。最初に実機で一度開いて確認することをおすすめします。
- ピンチ拡大・2 本指パン・長押しメニューは実装済みですが、マルチタッチの自動テストはしていません（マウス・ホイール・右クリック相当で確認）。
- iOS Safari は Canvas の上限が約 1,677 万画素のため、作品数が多い棚の 4x 書き出しは自動で倍率を下げます（保存後のトーストで実寸を表示）。
- プロジェクトは OneDrive 配下にあり、`node_modules`（数万ファイル）が同期対象になります。同期が重い場合は OneDrive の同期対象から外すか、別フォルダへの移動を検討してください。
- 次期の「追加ベースモデル（ローカット・ランニング・厚底）」は未着手です。`src/models/hightop01.ts` と同じ形のファイルを足し、`src/models/index.ts` に 1 行登録すれば追加できる構造にしてあります（`baseModel` の型にも ID の追加が必要）。
